## 1. What Factory is and sells

- Factory sells an "agent-native software development platform". Products: Droid CLI, Missions, Automations, a Public API, Droid Computers. Surfaces: CLI, desktop, web, mobile, Slack, Teams, Jira, Linear, CI. The landing page does not name an IDE. Source: https://factory.com/
- The docs index lists an IDE Integrations page (editors and any editor terminal). Source: https://docs.factory.com/llms.txt (title only, page not read).
- Pricing per month. Source: https://factory.com/pricing
  - Pro $20: desktop, CLI, SDK, cloud and local background agents.
  - Plus $100: about 5x Pro usage, plus Droid Computers (Factory-managed cloud machines).
  - Max $200: about 10x Pro usage.
  - Teams: $60 per team plus $40 per seat, up to 10 seats.
  - Business and Enterprise: contact sales. Business adds SSO/SAML/SCIM, Zero Data Retention, audit logging. Enterprise adds on-prem options, sub-organizations, data residency, SLAs.
  - No token counts are stated, only rate-limit multiples.
- Deployment: Managed or Private options, airgapped deployment with your own model endpoints, and OpenCompute (sandboxes in your own cloud). Source: https://docs.factory.com/llms.txt (descriptions only, pages not read).
- Models: Anthropic, OpenAI, Google, xAI, plus open models, bring-your-own-key, and a "Factory Router" that picks a model per task. Cost multipliers per model run from 0.04x to 12x. Source: https://docs.factory.com/models.md. The specific model names the summarizer returned (GPT-5.6, Claude Opus 5.5, etc.) were not cross-checked.
- Agent driven: Factory's own agent "Droid" only. I found nothing saying it supervises Claude Code or Codex. It is a competing harness, not a supervisor of other agents (unverified negative).

## 4. Top 5 ideas to borrow

1. Autonomy tier per move. Add a field such as `"autonomy": "read" | "edit" | "commit" | "push"` to each flow.json move. Bton refuses to start a job whose tool set exceeds the tier, so "review can never push" becomes a checked fact. Basis: droid-exec/overview.md.
2. Self-testing deny rules with a dry run. Each denied-tool rule carries `matches` and `doesNotMatch` example commands. Add a command like `bton rules check --command "git push"` and a UI row showing the decision. It catches the gap Factory itself warns about, where `git -C /repo push` slips past a prefix rule. Basis: permission-rules.md.
3. Auto-pause on repeated failure. After 5 consecutive failures a move shows Degraded, then Paused, in the menu bar, with a 7-day success rate and a missed-run alert. Resume is manual. This bounds unattended spend. Basis: automations/custom.md.
4. Readiness score per repo. A cheap check (tests, CI, AGENTS.md, branch protection, secret scanning) shown as a level per repo. Intake warns when a repo scores low. It reuses the feature registry. Basis: agent-readiness/overview.md.
5. Cost per outcome. Join existing per-job cost with GitHub data: cost per merged PR, review-to-merge time, rework rate, and an optional per-repo cap that pauses moves. Basis: agent-effectiveness/cost-and-productivity.md.

Honorable mention: a comment-only triage move that labels and flags duplicate issues before intake.

## 5. What not to copy

- Cloud computers and sandboxes (Droid Computers, Environments, OpenCompute): they need server and billing infrastructure, against Bton's Macs-plus-GitHub strength.
- Missions with orchestrator, workers and validators: Factory itself calls the benefit versus cost unresolved; flow.json moves with human gates are easier to reason about for a small team.
- Chat and ticket front doors (Slack, Teams, Jira, Linear, Google Chat): extra auth surface, and they break the GitHub-only state rule.
- Org hierarchy, SSO, SCIM, user groups: solve a problem a small team does not have.
- A proprietary harness and silent model router: Bton's value is supervising Claude Code and Codex; silent routing makes cost and behavior harder to audit.
- Shared service-account identity for delegated work: it blurs who asked for what. Keep per-person attribution.
